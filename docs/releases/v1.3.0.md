# SDR++ v1.3.0 · RX888 MkII on Linux · 免安装自包含包

Ready-to-run build of **SDR++ v1.3.0** for **RX888 MkII / BBRF103 (SDDC)** on Linux x86_64.
No compilation, no root (except a one-time device setup), no dependency hunting.

一个**解压即用**的完整构建：40 个模块、全部第三方依赖、FX3 固件都已打进包里。


## 为什么需要单独打包 / Why this is not just a `tar` of `make install`

上游 SDR++ 把两处路径**写死在二进制里**，直接拷贝安装目录换台机器必然起不来：

| 硬编码点 | 位置 | 后果 |
|---|---|---|
| `modulesDirectory` / `resourcesDirectory` | 编译进 `libsdrpp_core.so`（`INSTALL_PREFIX` 宏） | 指向构建机的绝对路径，找不到插件与资源 |
| `RUNPATH` | 每个 ELF | 指向构建机的本地依赖前缀，依赖全找不到 |

本包的处理方式：

- 用 `patchelf` 把**所有 ELF 的 RUNPATH** 改写成 `$ORIGIN` 相对路径 → 目录可任意搬迁；
- `run-sdrpp.sh` 用 `-r` 指向包内的独立配置目录，并首次运行时生成把两个路径改写为包内实际路径的 `config.json`。

> `config.cpp` 的 `load()` **不做深合并**（缺字段就是 `null`，不会回落到默认值），
> 所以包里带的是一份**完整**的默认配置模板，而不是只写两个字段的片段。

## 上游缺陷修复 / Upstream defects fixed

本包对应的源码树包含 **13 处上游缺陷修复**（`patches/` 目录），其中 3 处会导致
configure/install 阶段直接失败、2 处是真正的越界写：

- `sddc_source`（A-1…A-11，其中 A-13 属 `dab_decoder`）：固件路径硬编码成原作者的
  Windows 路径、GCC 14+ C23 下的隐式转换/声明错误、`realloc` 丢失返回值导致越界写、
  `moduleInstances` 缺少 SDDC 声明导致模块编出来但不出现在界面 等
- `dbab_decoder`：VOLK ≥ 3.1 的 `volk_32fc_s32fc_x2_rotator2_32fc()` 第三参数漏了 `&`
- `ExtIO_sddc`（A-12）：`usb_device_open()` 在固件上传后只等 500 ms 且只扫一次
  libusb 缓存列表，冷启动必然报 `usb_device@0 not found`

详见仓库 README 与 `patches/`。

## 已知限制 / Known limitations

- 面向 **Ubuntu 26.04 / glibc ≥ 2.39 / x86_64**；其它发行版可能因 glibc 版本过旧而无法运行。
- **图形栈（X11/Wayland/GLVND/Mesa）刻意不打进包**，由目标机提供 —— 它们必须与本机显卡驱动匹配。因此目标机需要可用的桌面/图形环境。
- 未包含需要闭源厂商 SDK 的模块：`sdrplay`（下载路径已失效且需 EULA + 系统守护进程）、`harogic`、`spectran`、`kcsdr`。
- `usrp` 未编译（会拖入整套 Boost dev，官方 Dockerfile 同样未编译）。
- `rfnm` / `perseus`：厂商库未完全编译成功。
- 原生 `sddc_source` 的增益/端口/调谐器控制仍是上游的注释状态（数据通路正常）。
- 13 处修复**尚未合入上游**，见 issue
  [AlexandreRouma/SDRPlusPlus#1819](https://github.com/AlexandreRouma/SDRPlusPlus/issues/1819)、
  [ik1xpv/ExtIO_sddc#250](https://github.com/ik1xpv/ExtIO_sddc/issues/250)。
